# Delivery Writing

Пиши по фактическому состоянию задачи, кода и PR. Не дополняй текст предполагаемым поведением и не превращай частный пример в обязательное правило для другого проекта.

Для любого русского текста сначала прочитай [правила русского технического текста](references/russian-writing.md). Затем открой только нужный справочник:

- для постановки Jira-задачи — [формат задачи](references/jira-task.md);
- для блока, который добавляется после реализации, — [рекомендации к тестированию](references/testing-recommendations.md);
- для описания PR — [краткое описание PR](references/pr-description.md);
- для текста комментариев коллегам — [комментарии к ревью](references/review-comments.md);
- перед пакетом в отдельной задаче публикации — [локальная ручная проверка](references/manual-smoke.md).

Рекомендации к тестированию составляй после реализации, когда доступны фактический diff, контракт и результаты проверок. До этого фиксируй только критерии готовности и открытые продуктовые вопросы.

По умолчанию готовь черновик в чате. Подготовка текста не разрешает создание или изменение PR, изменение Jira, публикацию комментария или разрешение обсуждения. Перед любым изменением Jira покажи полный предлагаемый блок `## Рекомендации к тестированию` и дождись явного подтверждения.

В отдельной задаче публикации сначала проверь переданные `run_id` и, если есть, `campaign_id` через Agent Harness, затем сверь пакет по текущему Git, Jira и PR и самостоятельно прочитай фактический diff от переданного базового SHA. Расхождение статуса, отпечатка diff, путей, проверок, ревью или Git останавливает подготовку публикации. После этой сверки и до показа пакета выполни локальную ручную проверку по справочнику. Подготовь одним сообщением описание сделанного, раздел `## Локальная ручная проверка`, точное сообщение коммита или его SHA, заголовок и короткое описание PR, полный блок `## Рекомендации к тестированию` и список предлагаемых внешних действий.

Только в отдельной задаче публикации после показа всего пакета команда `публикуем` разрешает явно перечисленные в нём создание локальной ветки или commit, push, создание или обновление PR и публикацию показанного блока в Jira. Вне такого пакета слово не расширяет разрешения. Перед записью ещё раз обнови состояние ветки, PR, проверок и Jira. Если оно отличается от показанного пакета, ничего не меняй: покажи обновлённый пакет и дождись нового подтверждения. Команда не разрешает merge, изменение статуса задачи, развёртывание, миграцию, непоказанные комментарии или другие внешние действия. Для комментариев к ревью по-прежнему показывай точные формулировки и жди отдельной команды.

После публикации эта же задача остаётся рабочим контекстом доставки: проверяй CI, обрабатывай замечания ревью и разбирай состояние или сбой развёртывания здесь. Не создавай для них новый пользовательский чат. Если требуется кодовый фикс, проведи его через `workflow`; развёртывание и миграция сохраняют отдельные границы разрешения.
