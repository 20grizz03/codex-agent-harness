# Delivery Writing

Пиши по фактическому состоянию задачи, кода и PR. Не дополняй текст предполагаемым поведением и не превращай частный пример в обязательное правило для другого проекта.

Для любого русского текста сначала прочитай [правила русского технического текста](references/russian-writing.md). Затем открой только нужный справочник:

- для постановки Jira-задачи — [формат задачи](references/jira-task.md);
- для блока, который добавляется после реализации, — [рекомендации к тестированию](references/testing-recommendations.md);
- для описания PR — [краткое описание PR](references/pr-description.md);
- для текста комментариев коллегам — [комментарии к ревью](references/review-comments.md);
- перед пакетом в отдельной задаче публикации — [локальная ручная проверка](references/manual-smoke.md).

Если текущая задача является задачей публикации, полностью прочитай [контекст задачи публикации](references/publication-context.md). Явный `publication_context.active: true` означает, что передавать этот пакет в следующую пользовательскую задачу нельзя. Для старых задач применяй описанные там признаки обратной совместимости.

Рекомендации к тестированию составляй после реализации, когда доступны фактический diff, контракт и результаты проверок. До этого фиксируй только критерии готовности и открытые продуктовые вопросы.

По умолчанию готовь черновик в чате. Подготовка текста не разрешает создание или изменение PR, изменение Jira, публикацию комментария или разрешение обсуждения. Перед любым изменением Jira покажи полный предлагаемый блок `## Рекомендации к тестированию` и дождись явного подтверждения.

В отдельной задаче публикации сначала проверь все переданные `source_run_ids` и, если есть, `campaign_id` через Agent Harness, затем сверь пакет по текущему Git, Jira и PR и самостоятельно прочитай фактический diff от каждого переданного базового SHA. Расхождение статуса, отпечатка diff, путей, проверок, ревью или Git останавливает подготовку публикации. После этой сверки и до показа пакета выполни локальную ручную проверку по справочнику. Подготовь одним сообщением описание сделанного, размеры рабочего кода, тестов, документации и конфигурации, сгенерированных и бинарных файлов, статус мягкого бюджета и объяснение связного превышения при наличии, раздел `## Локальная ручная проверка`, точное сообщение коммита или его SHA, заголовок и короткое описание PR, полный блок `## Рекомендации к тестированию` и список предлагаемых внешних действий. Рекомендации описывают только поведение текущего PR, даже если он входит в большой эпик.

Только в отдельной задаче публикации после показа всего пакета однозначная команда пользователя разрешает названные в ней действия из показанного списка. Формулировка не обязана совпадать с `публикуем`: например, `пушим поверх` разрешает показанные commit и обычный push без `--force`, а `создавай PR` — только показанное создание или обновление PR. Если команда называет часть пакета, выполняй только её. Вне показанного пакета такая фраза не расширяет разрешения.

Перед первой записью ещё раз обнови состояние ветки, PR, проверок и Jira. Если оно отличается от показанного пакета, ничего не меняй: покажи обновлённый пакет и дождись нового подтверждения. После временного сбоя повторяй уже разрешённое действие без новой команды, пока кандидат, целевая ветка и список действий не изменились. Новый пакет и подтверждение нужны при изменении diff или commit, другой ветке, force-push либо добавлении внешнего действия. Разрешение не включает merge, изменение статуса задачи, развёртывание, миграцию, непоказанные комментарии или другие внешние действия. Для комментариев к ревью по-прежнему показывай точные формулировки и жди отдельной команды.

С момента получения `publication_context` эта задача остаётся единственным рабочим контекстом пакета: подготовь публикацию, проверь CI, обработай замечания ревью и разбери состояние или сбой развёртывания здесь. Не создавай для этого `scope_id` новый пользовательский чат ни до, ни после первой внешней записи. Если требуется кодовый фикс, проведи его через `workflow` и верни результат сюда; развёртывание и миграция сохраняют отдельные границы разрешения.
