# Сопровождение публикации

Следующие правила применяются только при подготовке или сопровождении пакета реализации для публикации. Обычный черновик, в том числе отдельная Jira-задача или комментарий, не включает этот режим. Для отдельной разрешённой записи сверяй соответствующий целевой объект и согласованный текст, без поиска не относящихся к ней прогонов, веток и PR.

Перед публикационным пакетом полностью прочитай [контекст публикации](publication-context.md) и [локальную ручную проверку](manual-smoke.md). Явный `publication_context.active: true` означает, что текущая пользовательская задача уже владеет пакетом и не должна передавать его дальше. Для старых задач применяй описанные там признаки обратной совместимости.

При серверном `terminal.verification_reuse` проверяй и показывай происхождение исходного ревью и перечисленные несемантические исправления по этому справочнику. Не требуй новое ревью только из-за уже проверенной сервером разницы, но не распространяй исключение на другие изменения.

Для мелкого исправления в активной задаче публикации сначала выбери режим [мелких доработок](publication-context.md#мелкие-доработки). Он допускает правку кода без нового прогона, обязательных тестов, ручной проверки и независимого ревью. Кратко обозначь исправление, внеси его, сам прочитай diff и покажи обновлённый пакет с явным указанием непроверенной доработки. Не запрашивай повторное разрешение на локальную правку внутри уже согласованной задачи.

Если у исправленного кандидата есть зависимые PR, прочитай [цепочку корректировки](../../workflow/references/correction-chain.md). Текущий контекст исправляет только свой исходный кандидат и передаёт ведущему эпика точный полный SHA; зависимые ветки не обновляй параллельно из нескольких публикационных контекстов. Перед публикацией зависимых кандидатов сверь их ссылки на проход, собственную сборку каждого PR и затронутые тесты конечных кандидатов с накопленным объёмом изменений предков. `mechanical_checked` не называй `complete` или свежим независимым ревью.

В текущей задаче сначала проверь все `source_run_ids` и, если есть, `campaign_id` через Agent Harness, затем сверь пакет по текущему Git, Jira и PR. Для стандартного кандидата самостоятельно прочитай полный результат от его базового SHA; расхождение статуса, отпечатка, путей, проверок, актуального ревью или Git останавливает весь пакет. Для мелкой доработки отдельно сверь неизменённую проверенную основу и весь накопленный diff доработок по правилам справочника; старые проверки не относятся к новому результату. Для механически обновлённой цепочки сверь `followup_ref` каждого кандидата, сохранённый собственный диапазон коммитов, текущие SHA, сборку каждого PR и затронутые тесты конечных кандидатов с накопленным объёмом изменений предков; не подменяй это проверками старого прогона. После сверки выполни локальную ручную проверку, кроме режима мелкой доработки. Подготовь одним сообщением описание сделанного, размеры рабочего кода, тестов, документации и конфигурации, сгенерированных и бинарных файлов, статус мягкого бюджета, раздел `## Локальная ручная проверка` с фактическим результатом или причиной пропуска, commit, заголовок и короткое описание PR, полный блок `## Рекомендации к тестированию` и список предлагаемых внешних действий.

После показа всего пакета однозначная команда пользователя разрешает названные в ней действия из показанного списка. Формулировка не обязана совпадать с `публикуем`: например, `пушим поверх` разрешает показанные commit и обычный push без `--force`, а `создавай PR` — только показанное создание или обновление PR. Если команда называет часть пакета, выполняй только её. Вне показанного пакета такая фраза не расширяет разрешения.

Перед первой записью ещё раз обнови состояние ветки, PR, проверок и Jira. Если оно отличается от показанного пакета, ничего не меняй: покажи обновлённый пакет и дождись нового подтверждения. После временного сбоя повторяй уже разрешённое действие без новой команды, пока кандидат, целевая ветка и список действий не изменились. Новый пакет и подтверждение нужны при изменении diff или commit, другой ветке, force-push либо добавлении внешнего действия. Разрешение не включает merge, изменение статуса задачи, развёртывание, миграцию, непоказанные комментарии или другие внешние действия. Для комментариев к ревью по-прежнему показывай точные формулировки и жди отдельной команды.

С момента установки `publication_context` эта задача остаётся рабочим контекстом пакета: подготовь публикацию, проверь CI, обработай замечания ревью и разбери состояние или сбой развёртывания здесь. Отдельную свежую задачу создавай только по явному выбору пользователя. Кодовый фикс сначала оцени на применимость режима мелкой доработки; механический перенос веди по цепочке корректировки, а смысловую правку — через новый ограниченный `workflow`, затем верни результат сюда. Развёртывание и миграция сохраняют отдельные границы разрешения.
