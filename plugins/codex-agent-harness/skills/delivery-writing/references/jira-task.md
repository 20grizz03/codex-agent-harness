# Постановка Jira-задачи

Используй краткую структуру ниже и сверяй содержание с текущим репозиторием и проектным шаблоном. Примеры условные; реальные ссылки и идентификаторы бери только из текущей задачи.

## Заголовок

Для репозиторной задачи используй форму:

```text
[<сервис>] <действие> <объект или результат>
```

Условные примеры: `[catalog-api] Добавить импорт товаров из CSV`, `[catalog-api] Добавить фильтр по категории`.

## Описание

Начинай с раздела `Что сделать` (`## Что сделать` в Markdown-черновике). Обычно достаточно нескольких коротких абзацев в таком порядке:

1. Наблюдаемый результат для пользователя или системы.
2. Точный контракт: HTTP-метод и путь, поля, допустимые значения, статусы и переходы состояния.
3. Важные инварианты: идемпотентность, пагинация, обработка ошибок, защита данных, совместимость.
4. Границы задачи: что переиспользовать, что не менять и что явно не входит в объём.
5. Связанные задачи или документы, только если без них нельзя понять зависимость.

Показывай запросы, ответы и конфигурацию в кодовых блоках с безопасными заполнителями: `<api>`, `<token>`, `<event_id>`. Не вставляй реальные токены, персональные данные и адреса получателей.

Не навязывай внутреннюю реализацию, если она не является архитектурным ограничением или частью контракта. Не придумывай решение для открытого продуктового вопроса: вынеси его как явный вопрос и останови реализацию, если ответ меняет поведение.

Не заполняй окончательные рекомендации к тестированию на этапе постановки. Добавь их после реализации по [отдельному формату](testing-recommendations.md), когда известны фактический diff и PR.
