# Локальная ручная проверка

Используй этот справочник в текущем контексте публикации после сверки Agent Harness, Git и фактического изменения, но до показа пакета.

Для [мелкой доработки](publication-context.md#мелкие-доработки) обязательного ручного прогона нет. Укажи статус `не запускалась`, причину `режим мелкой доработки` и ограничения; не переноси результат проверки исходной версии на новый код. Следующие требования автоматического запуска и повторения относятся к стандартному пути. При конкретной необходимости или явной просьбе пользователя выполни безопасную проверку и запиши фактический результат.

## Выбор сценария

Выбери из утверждённого контракта и фактического изменения один минимальный основной сценарий, который проверяет изменённое поведение через уже доступный локальный интерфейс, API или CLI. Добавляй одну отрицательную или регрессионную ветку только тогда, когда изменение непосредственно её затрагивает. Для документации, инструкций и другого неисполняемого результата отметь проверку как неприменимую.

## Безопасность запуска

Перед любыми тестами, приложением, сервером, воркером или миграцией проверь `.env`, конфигурацию и направления исходящего трафика: очереди, почту, Redis, RabbitMQ, Kafka, внешние API, хранилища, webhooks, аналитику, SMS и push. Используй только локальные, поддельные или явно изолированные сервисы, данные и получателей.

Не обращайся к test, stage, production, общим очередям, внешним сервисам или реальным каналам уведомлений. Не устанавливай ради сценария новый инструмент или зависимость. Если безопасно изолировать запуск нельзя либо локальный интерфейс недоступен, ничего не запускай, укажи конкретную причину и продолжай подготовку пакета.

## Выполнение и результат

Перед запуском зафиксируй проверенные `HEAD`, состояние рабочего дерева и текущий `diff_fingerprint`. Выполни сценарий без отдельной команды пользователя и запиши только способ запуска и наблюдаемый результат:

- если результат соответствует критериям готовности, статус — `пройдена`;
- для неисполняемого изменения статус — `неприменима`;
- при отсутствии локального способа статус — `недоступна`;
- если запуск нарушил бы безопасную границу, статус — `небезопасна`;
- если кандидат воспроизводимо расходится с утверждённым контрактом, не публикуй неисправную версию; исправление в этой же задаче направь в режим мелкой доработки, если оно отвечает его условиям, иначе в `workflow`.

После проверки повторно сверь `HEAD`, рабочее дерево и изменение с проверенным кандидатом. Если состояние Git изменилось, не используй прежний результат: снова проверь кандидат и повтори сценарий. Неизвестное изменение рабочего дерева останавливает подготовку пакета.

## Раздел пакета

Добавь отдельный раздел:

```markdown
## Локальная ручная проверка

- Статус: пройдена | неприменима | недоступна | небезопасна | не запускалась
- Сценарий: <что проверялось>
- Способ: <локальный UI, API или команда; для пропуска — «не запускалась»>
- Наблюдаемый результат: <фактический результат или конкретная причина пропуска>
- Ограничение: <чего эта проверка не подтверждает>
```

Не включай необработанные журналы, секреты или персональные данные. Этот раздел не заменяет рекомендации QA. Любая однозначная команда на публикацию, включая `публикуем` или `пушим поверх`, разрешает только названные действия из показанного пакета. Она не разрешает повторять проверку во внешнем или общем окружении и сохраняет прежние границы разрешения.
