# Исправления после независимого ревью

Обычное исправление кода требует актуальных обязательных проверок и свежего независимого ревью. Повторный критик получает прежние замечания, решения по ним и изменённые пути. Если прошлый кандидат был чистым коммитом, `correction_review.mode: correction` закрепляет его SHA: проверить исправления, разницу и затронутые связи. При существенно изменившейся реализации область расширяется с объяснением. Отклонённое замечание повторяется только при новом подтверждении. При недоступной базе или старом состоянии без снимка используется `full`.

## Несемантическое завершение незавершённого прогона

Если остались только редакционные P3-замечания, не запускай полный цикл модели автоматически. Сначала проверь фактическое исправление: смысл контракта, поведение, инструкции, безопасность и конфигурация не меняются. Размер файла сам по себе этого не доказывает.

1. Запиши замечания как `accepted`, пока `resolved: false`; неверные замечания — `rejected` с подтверждением и `resolved: true`.
2. Исправь только указанные документы. Допустима также исключительно пометка `// indirect` в корневом `go.mod`, без смены модулей, версий и директив. Не запускай `go mod tidy` ради такой правки.
3. Вызови `plan_checks(nonsemantic_closeout: true)`. Сервер сравнит сохранённый снимок ревью с текущими файлами и индексом Git, включая режимы и стадии. Изменённый индекс должен содержать именно проверяемую рабочую версию, а не скрытую третью версию файла. Допускаются существующие обычные README и файлы документации из `docs/` или `documentation/`, соответствующие принятым P3. Добавления, удаления, переименования, изменения режима файлов, кода, инструкций, контрактов и остальной конфигурации требуют обычного пути. Старые прогоны без полного снимка не получают исключения.
4. Выполни возвращённые проверки и запиши результаты. Проверь содержание исправлений и закрой замечания через `record_review_resolution`; затем `finish_run(complete)`. Этот путь не расходует корректировочный проход модели, но не отменяет проверок и не скрывает незакрытых замечаний.

`review_reuse` / `terminal.verification_reuse` указывают исходный и текущий отпечатки и исправленные пути. Исходное ревью не переписывается и не называется новым. При публикации показывай: «рабочая реализация прошла независимое ревью; затем исправлены перечисленные P3 без нового вызова модели, обязательные проверки повторены». Новый код и неопознанное расхождение нельзя выдавать за это исключение.

Если сервер отклонил путь, не подменяй поля состояния, тяжесть замечания или результат ревью. Используй обычный корректировочный проход либо показывай реальную причину остановки. Это исключение отличается от мелкой публикационной доработки уже завершённого кандидата с явно непроверенной разницей.
