# Пример общей спецификации: уведомления о доставке

Это пример содержания `.agent-harness/specs/delivery-status/spec.md`, а не обязательный шаблон или перечень заголовков.

Сервис принимает статусы провайдера и показывает последний подтверждённый статус пользователю. При повторе одного события результат не меняется. Статус не может переходить назад из `delivered` в `sent`. Неизвестный идентификатор сообщения не создаёт запись.

Общая граница: входной адаптер проверяет подпись, слой обработки применяет допустимые переходы, хранилище обеспечивает атомарность. Контракт провайдера закреплён отдельной ссылкой с версией в `contract_refs`; секрет подписи не попадает в логи. При временной ошибке хранилища событие допускает повтор без потери и дублирования наблюдаемого результата.

Задачи разделены по наблюдаемому поведению: приём и безопасное применение статуса провайдера; получение последнего статуса через API. Первая задача включает HTTP-адаптер, проверку подписи, допустимые переходы и сохранение: эти части нельзя выпускать по отдельности. Вторая добавляет отдельно проверяемое чтение и зависит от первой. Публикация сохраняет совместимость текущего ответа API; откат отключает новые операции, не удаляя уже записанные статусы. Проверки эпика подтверждают, что принятый статус доступен через чтение, а повтор или устаревшее событие не меняет результат.
